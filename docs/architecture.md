# Архитектура модуля безопасности персональных данных

## Схема

```
Система-потребитель
        │
        │ POST /process {payload, payload_id}
        ▼
┌─────────────────────────────────────────────────────────────┐
│                    Модуль безопасности ПД                   │
│                    (FastAPI, uvicorn --workers 1)           │
│                                                             │
│  ┌──────────┐   ┌──────────────┐   ┌─────────────────────┐  │
│  │  /process │──▶│  Pipeline    │──▶│  Детекторы (15)     │  │
│  │ (эндпоинт)│   │ (3 ветки)    │   │  regex+морфология+  │  │
│  └──────────┘   └──────┬───────┘   │  эвристики           │  │
│                        │           └──────────┬──────────┘  │
│                        │                      │             │
│                        │           ┌──────────▼──────────┐  │
│                        │           │  Резолвер           │  │
│                        │           │  пересечений        │  │
│                        │           └──────────┬──────────┘  │
│                        │                      │             │
│                        │           ┌──────────▼──────────┐  │
│                        │           │  Маскирование       │  │
│                        │           │  (сохранение длины) │  │
│                        │           └──────────┬──────────┘  │
│                        │                      │             │
│                        │           ┌──────────▼──────────┐  │
│                        │           │  Vault (LRU+TTL)    │  │
│                        │           │  payload_id→{mask,  │  │
│                        │           │  original}          │  │
│                        │           └──────────┬──────────┘  │
│                        │                      │             │
│                        ▼                      ▼             │
│              ┌─────────────────────────────────────────┐    │
│              │  Config (systems.yaml)                  │    │
│              │  Observability (логи, метрики)          │    │
│              └─────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
        │
        │ {"result": "маска"}  (прямой шаг)
        │ {"result": "original"} (обратный шаг)
        ▼
Система-потребитель → LLM (маскированный текст)
LLM → ответ → Модуль (демаскирование) → Потребитель
```

## Поток обработки

### Прямой шаг (маскирование)
1. `POST /process` с новым `payload_id` и исходным текстом.
2. Pipeline: id неизвестен → маскирование.
3. Детекторы (15 типов) находят спаны ПД.
4. Резолвер разрешает пересечения (приоритет типа → длина → уверенность, контрольные суммы выше).
5. Маскирование по эталону ТЗ: ФИО → инициалы (`И. И. И.`), паспорт → `45** ****56`, карта → последние 4 цифры, телефон → код страны, ИНН → последние 2, дата → год. Разделители сохраняются.
6. Соответствие `payload_id → {mask, original}` сохраняется в Vault.
7. Возвращается `{"result": "маска"}`.

### Обратный шаг (демаскирование)
1. `POST /process` с тем же `payload_id` и маской.
2. Pipeline: id известен, payload == mask → демаскирование.
3. Vault возвращает `original`.
4. Возвращается `{"result": "original"}`.

### Ретрай (идемпотентность)
1. `POST /process` с тем же `payload_id` и тем же исходным текстом.
2. Pipeline: id известен, payload == original → возвращается сохранённая маска.

### Чанкование больших текстов
Текст длиннее 50 000 символов разбивается на чанки с перекрытием 200 символов
(чтобы многословное ПД, пересекающее границу, не терялось), обрабатывается
параллельно, результаты склеиваются.

## Ключевые решения

| Решение | Обоснование |
|---|---|
| `--workers 1` | Vault живёт в памяти процесса; на нескольких воркерах демаскирование ломается |
| Роутинг из 3 веток | Различает ретрай маскирования и обратный шаг |
| Маска по эталону ТЗ | ФИО → инициалы, открытые символы по типам (паспорт 45** ****56) |
| Детектор = файл | Расширяемость без правки ядра |
| `/process` не отдаёт 4XX/5XX | Проверяющая система останавливает прогон после 5 невалидных ответов |
| Allowlist систем | Система вне allowlist получает payload без маски (200) |
| Отключённая система | Маскирует, но не демаскирует (только маска) |

## Конфигурация

- `config/systems.yaml`: список систем (вкл/откл), перечень типов ПД, наличие демаскирования, вид маски, `multi_type_rule`, `allowed_systems` (allowlist).
- `default_system` применяется, когда `X-System-Id` отсутствует (всегда для проверяющей системы).
- Отключённая система (`enabled: false`) маскирует, но не демаскирует.
- Новый тип ПД = новый файл в `app/detectors/`.
