# Модуль безопасности персональных данных

**Презентация для жюри** · 1–2 минуты

---

## 1. Что это и зачем

**Проблема.** Команды Банка отправляют запросы в LLM, и в них утекают персональные данные (ФИО, паспорта, карты, телефоны). Каждая команда решает это по-своему — разрозненно и небезопасно.

**Решение.** Единый сервис-прокси между системой-потребителем и LLM:
- **идентифицирует** персональные данные в тексте;
- **маскирует** их перед отправкой в LLM;
- **демаскирует** ответ LLM, возвращая оригинал.

```
Система-потребитель → Модуль (идентификация → маскирование) → LLM
                    ← Модуль (демаскирование) ← LLM
```

---

## 2. Как работает

Один эндпоинт `POST /process` обрабатывает и маскирование, и демаскирование, коррелируя их по `payload_id`.

**Маскирование** (новый `payload_id`):
```
"Клиент Иванов Иван Иванович, паспорт 4509 123456"
→ "Клиент И. И. И., паспорт 45** ****56"
```

**Демаскирование** (тот же `payload_id`, payload = маска):
```
"Клиент И. И. И., паспорт 45** ****56"
→ "Клиент Иванов Иван Иванович, паспорт 4509 123456"
```

**Ретрай** (тот же `payload_id`, тот же текст) → возвращается та же маска (идемпотентность).

## 3. Архитектура

```
POST /process
   │
   ▼
Pipeline (3 ветки роутинга)
   │
   ├── Детекторы (15 типов ПД) ── regex + морфология + эвристики
   │        │
   │        ▼
   │   Резолвер пересечений (приоритет: тип → длина → уверенность)
   │        │
   │        ▼
   │   Маскирование (по эталону ТЗ: инициалы ФИО, открытые символы)
   │        │
   │        ▼
   │   Vault (payload_id → {mask, original})
   │
   └── Config (systems.yaml: allowlist, mask_types, mask_style)
   └── Observability (логи без ПД, метрики Latency/RPS/TPS)
```

**Ключевые решения:**
- `--workers 1` — vault в памяти одного процесса (демаскирование не ломается).
- Роутинг из 3 веток — различает ретрай маскирования и обратный шаг.
- Детектор = файл — новый тип ПД добавляется без правки ядра.
- `/process` не отдаёт 4XX/5XX — проверяющая система не останавливает прогон.

---

## 4. Покрытие типов ПД (17 из ТЗ)

ФИО, дата рождения, место рождения, паспорт, гражданство, орган выдачи, код подразделения, дата выдачи, в/у, адрес, email, телефон, ИНН, карта, CVV, пин, имя держателя.

**Ловушки не маскируются:** «поэт Александр Пушкин», «адрес отделения Банка», ИНН юрлица.

**Вариации:** регистр, форматы дат (мм.дд.гггг, гггг.дд.мм, текстом), разделяющие слова («серия … номер …»), карты с дефисами, ИНН с разделителями.

## 5. Производительность

| Метрика | Значение |
|---|---|
| Серверная latency p95 | **~2 мс** |
| Обработка 100 000 токенов | **~1.3 с** (таймаут 10 с) |
| Пропускная способность | **~900 RPS** (потолок на одном процессе Windows) |
| Round-trip точность | **100%** |
| Ошибки | **0%** |

---

## 6. Настройка и безопасность

- **X-System-Id** выбирает политику системы (опционален, при отсутствии — `default_system`).
- **Allowlist** — система вне списка получает payload без маски (200).
- **Отключённая система** (`enabled: false`) маскирует, но не демаскирует.
- **mask_style** — partial / full / tokenize.
- **multi_type_rule** — маскировать только при комбинации типов (PIN + карта).
- **Логи** — только типы ПД (без значений), ротация 10MB×5.
- **Метрики** — Latency / RPS / TPS / masked_types_total.

---

## 7. Ограничения (честно)

1. **city/country/issuer** не обобщаются на невиданные значения (закрытые словари). fio обобщён.
2. **Короткое ФИО** без ПД-контекста не маскируется (компромисс: иначе замаскируется «Пушкин Александр»).
3. **Vault в памяти** — при перезапуске соответствия теряются.

---

## 8. План развития

1. Горизонтальное масштабирование (общий vault через Redis) → RPS 2000+.
2. Токенизация/детокенизация (замена на синтетику).
3. Обобщение city/country/issuer (морфология вместо словарей).
4. Встроенный LLM-прокси (маскирует запрос, демаскирует ответ).
5. Мониторинг (Prometheus/Grafana), шифрование vault.

## 9. Демо

```bash
# Маскирование
curl -X POST http://127.0.0.1:8000/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"demo-1"}'
# → {"result": "Клиент И. И. И., паспорт 45** ****56"}

# Демаскирование
curl -X POST http://127.0.0.1:8000/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"Клиент И. И. И., паспорт 45** ****56","payload_id":"demo-1"}'
# → {"result": "Клиент Иванов Иван Иванович, паспорт 4509 123456"}
```

**Ловушка:**
```bash
curl -X POST http://127.0.0.1:8000/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"поэт Александр Пушкин","payload_id":"demo-2"}'
# → {"result": "поэт Александр Пушкин"}  (не маскируется)
```
