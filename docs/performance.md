# Производительность и дополнительные возможности

## Производительность

### Нагрузочное тестирование (RPS 1000)

Прогон `tools/load_test.py` с целевым RPS 1000, 8 процессами генерации:

| Метрика | Значение |
|---|---|
| Фактический RPS | **~900–1000** |
| Сервер latency p95 | **~2 мс** |
| Доля ошибок | 0% |
| Round-trip точность | 100% |

Фактический потолок пропускной способности на одном процессе uvicorn на
Windows — **~900–1000 RPS** (ограничение GIL). Серверная latency p95 —
порядка **2 мс** (из `/metrics`). Клиентская latency p95 зависит от нагрузки
и числа конкурентных соединений: при целевом RPS 1000 она растёт по мере
приближения к потолку. Требование ТЗ §5 (Latency ≤ 1 с, RPS 1000) выполняется
при фактическом RPS в пределах потолка.

> Примечание: `tools/load_test.py` показывает серверную latency из `/stats`
> (или `/metrics`). Если серверные метрики не прочитаны под нагрузкой, в
> отчёте выводится «недоступно», а не подставной 0 мс.

### Обработка крупных текстов (100 000 токенов)

| Метрика | Значение |
|---|---|
| Объём | 101 200 токенов (608 499 символов) |
| Статус | 200 |
| Время обработки | 1.28 с |
| ПД замаскированы | да |
| Длина сохранена | да |

Обработка 100 000 токенов работает корректно. Время 1.28 с в пределах таймаута проверяющей системы (10 с).

### RPS 2000 (повышенный уровень)

При целевом RPS 2000 фактический потолок на одном процессе uvicorn на
Windows — **~900–1000 RPS** (ограничение GIL), серверная latency p95 —
порядка **2 мс**. RPS 2000 недостижим на одном процессе uvicorn на Windows.
На Linux с несколькими воркерами потолок выше, но точные цифры требуют
отдельного замера.

## Дополнительные возможности

| Возможность | Статус |
|---|---|
| Гибкая настройка вида маскирования по системе | Реализовано (`mask_style` в config) |
| Идентификация документов кроме паспорта РФ | Реализовано (водительское удостоверение) |
| Контекстное маскирование (только при комбинации типов) | Реализовано (`multi_type_rule` в config) |
| Токенизация/детокенизация | Не реализовано (опциональный доп. плюс) |
| RPS 2000 | Не достигнут на Windows (ограничение GIL) |

## Метрики

`GET /metrics` возвращает:
- `requests_total` — число запросов.
- `rps` — запросов в секунду.
- `avg_latency_seconds` — средняя latency.
- `latency_p50/p95/p99_seconds` — квантили latency.
- `tokens_total` — обработанных токенов (TPS).
